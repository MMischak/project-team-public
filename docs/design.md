# Workspace design

Tinkrew uses a quiet, light work surface: a clear next decision, useful team identities, readable plans and a persistent manager conversation. Match the model and reasoning effort to the task; let the work remain the focus.

## Visual language

- A system sans-serif stack, with restrained weights, sentence-case headings and a clear type scale. No external font request is required.
- White surfaces, deep ink text/actions, blue selection and focus, and green for actual ready/completed states.
- Spacing, alignment and fine dividers establish hierarchy. Panels and elevation are reserved for objects, conversations and dialogs.
- Original fictional portraits use a playful animated-film style, with expressive features, sculpted hair, soft light and quiet pastel backgrounds. The manager and up to eight members each have a distinct face; identity follows the member across projects, rather than following the role.
- Model, reasoning effort and attributable usage stay visible. A portrait or model label does not imply automatic task routing or a guaranteed cost.

The [visual target](assets/design-target.png) is a design concept with synthetic content. The [workspace capture](assets/workspace.png) shows the implemented application using its actual demo fixture and reported demo counters.

The target remains a reference for the approved layout; its earlier photographic character treatment has been replaced. The fixed character library makes hiring visually distinct without generating new images or making image-service calls during a session.

## Interaction and responsive behavior

Reviewing a proposed plan opens its assignments, outputs, dependencies and estimated usage. It does not approve the plan, dispatch tasks or reserve credits. The separate **Approve plan** action starts the existing approved workflow.

Keep project credits visible at every width. On small screens navigation becomes a compact row and the manager conversation follows the work. Dialogs scroll within the viewport, preserve keyboard focus and expose a separate close action. Respect reduced-motion preferences.

The sidebar lists saved projects and a separate New project action. One shared crew works on the selected project. A switch first saves/drains work, then opens the destination paused and disconnected; it does not authorize a new turn. Project views and attachments reset at the boundary, while unsent manager drafts stay in browser memory under their project until sent or the page closes.

Apply this language consistently to hiring, team profiles, meetings, captured outputs, recovery, GitHub previews and storage settings. Preserve truthful loading, offline, paused, working and review states.

## References and privacy

The direction draws on the clarity of [firma.de](https://www.firma.de/), the restrained controls discussed in [Linear's interface refresh](https://linear.app/now/behind-the-latest-design-refresh), and the concrete work surfaces of [Attio](https://attio.com/). These are references for craft and hierarchy, not copied brand assets.

Keep reference screenshots, rejected concepts, raw prompts and private discussions outside public source. Public portraits and concept/capture images contain synthetic content and have their ancillary provenance/personal metadata removed. Use the publication check and inspect every image before publishing.
